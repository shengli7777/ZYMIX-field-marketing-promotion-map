# ZYMIX 地推点位工作台

我结合地推工作中的选址和反馈需求做了这个网页，主要用于伦敦，也支持录入其他英国城市。

## 平时怎么用

1. 登录后，输入候选地点并确认地图位置。
2. 选择场地类型和室内外环境。不确定的先留在“待确认”。
3. 查询周边600米的公开设施，作为选址参考。建议评分由使用者确认后保存。
4. 排班继续在团队现有的 Google 表格里完成。
5. 活动结束后，Roderick 在工作台独立填写反馈，不需要先创建排班。
6. 查看每人时注册数、扫码转化率和每个注册的成本，比较活动效果。

同一天两个独立小组分别填写，通过推荐码区分。两人各做两小时就是4人时。成本、扫码量未知时留空，确实为零才填0。

## 保存与团队使用

地点、场地分类、位置、确认状态、评分和活动反馈保存到 Supabase。周边设施与初筛报告仅在当前页面临时缓存一小时，尚未保存到数据库。建议评分需要勾选并确认保存。

点击“刷新数据”查看其他成员的新记录。活跃状态表示最近打开工作台的时间，不代表工时，不记录输入内容。同一标签页刷新可恢复登录；退出会清除会话。

未登录的活动是演示数据。登录后读取真实团队记录。本版隐藏工作台排班入口，不加载旧排班；数据库中的旧排班和反馈关联仍保留，不删除。Google 表格没有自动同步，暂未配置跳转链接。

## 初筛能做什么

Photon 用于搜索地点，OpenStreetMap / Overpass 提供附近设施记录。查询先按小范围矩形筛选，再按600米直线距离过滤，并合并近距离同名同类记录。距离以地图点或面中心计算，不能代替步行路线。

初筛尚未接入 AI、真实区域人流或许可查询。两类及以上学习、消费、休闲设施给人群匹配提供3分建议；查到交通站点给交通提供3分建议。这是固定的试用规则，不是效果预测，也不能推断年轻人比例。其余分数需要人工判断。没有历史活动不会扣分。

公共接口偶尔会超时，可稍后重试；失败不会修改已有评分。暂适合少量候选点试用，正式扩大使用需考虑稳定的数据服务。页面中的考察提示只是资料核实建议，工作台没有强制踩点步骤。

## 更新方法

如果尚未运行过 venue-update.sql，先在 Supabase SQL Editor 执行一次，增加场地分类字段。已经成功运行则不必重复。

然后覆盖 app.js、cloud.js、index.html、style.css、screening.js、README.md 六个文件。Live Preview 验证后上传原 GitHub 仓库。无需删除旧数据，也不用重做账号或数据库初始化。

数据库沿用已有 RLS 和成员权限。浏览器里的 publishable key 是公开连接配置，不能把 secret key、service_role 或数据库密码放到仓库。
